# Architectural Decisions

Index of the decisions that shape Resonant. The decision records themselves
are in `docs/decisions/` (one file per decision, manifest
`docs/decisions/decisions.txt`); this file is a reading guide, not a second
source of truth. Records numbered below 000204 concern the
development-control system, not the application.

| Record | Decision | Milestone |
|---|---|---|
| [ADR-000204](docs/decisions/ADR-000204-technology-stack-and-dual-build-system.md) | C++20, Qt 6 Widgets, OpenGL 4.5 Core, Eigen, nlohmann-json; CMake and qmake build the same sources; GoogleTest vendored; user interfaces are `.ui` forms | M0 |
| [ADR-000205](docs/decisions/ADR-000205-layered-architecture-and-physics-domains.md) | Layers core / render / app with a Qt-free core; physics domains as separate modules; engineering geometry distinct from meshes; SI units, Z-up, radians, Z-Y-X Euler angles; results carry their model and assumptions; jobs off the UI thread; CPU reference before GPU | M0 |
| [ADR-000206](docs/decisions/ADR-000206-application-foundation-design.md) | One editable state per object and immutable domain components; geometry kinds as registry data; commands on one stack; a document controller; draw items instead of scene objects in the renderer; project format 1; the application as a library plus an executable; globbed sources; moc kept away from standard headers; display units in the application | M1 |
| [ADR-000207](docs/decisions/ADR-000207-acoustic-engine-design.md) | Acoustic conventions (`e^{+jωt}`, peak amplitudes), source strength as pressure at 1 m, explicit medium, one propagation interface, near-source clamping, intensity from particle velocity, arrays as one object with overrides, phase and delay focusing as distinct settings, SVD inverse design, results as snapshots, display from stored data | M2 |
| [ADR-000208](docs/decisions/ADR-000208-wave-manipulators-and-reflector-model.md) | Manipulators as scene objects with design data, parametric geometry and a separate simulation representation; support levels; a Kirchhoff reflector model as a selectable propagation model; the field model as a recorded project setting; rays as a geometric aid; minimal optimization interfaces; constraints as checks | M3 |
| [ADR-000209](docs/decisions/ADR-000209-full-wave-fdtd-solver.md) | Staggered-grid FDTD as the first full-wave solver, validated as a scene-independent core; split-field PML; calibrated soft sources; 2D as a stated different problem; simulation geometry from definitions; solids as fluids; steady state as an ordinary field result; a solver registry that assesses and never selects; refuse rather than degrade | M4 |
| [ADR-000210](docs/decisions/ADR-000210-mechanical-domain.md) | Mechanical domain with an own finite-element core; explicit idealizations; frame, ACM plate, membrane and hexahedral elements; Lanczos eigensolver with residuals; explicit damping models; Newmark transients; shared dsp module; separate coupling module | M5 |
| [ADR-000211](docs/decisions/ADR-000211-electromagnetic-domain.md) | Electromagnetic domain: analytical thin-wire antennas and induced-EMF impedance; arrays as an array-factor model without coupling; an own Yee FDTD solver (split-field PML, PEC, thin wires, 2D TM); setup separate from numerics with refusal instead of coarsening; simulation bodies shared in the geometry module; guide objects; one-port Touchstone; a dB field view | M6 |
| [ADR-000212](docs/decisions/ADR-000212-compute-backends.md) | Compute backends: a domain-independent compute module; deterministic CPU threads (bit-identical, ordered reductions) with chunked scheduling; a stepper interface per full-wave solver; CUDA as an optional, statically linked backend with the reference arithmetic (no FMA) and refusal instead of fall-back; VOLK only for single-precision data | — |
| [ADR-000214](docs/decisions/ADR-000214-optimization-framework.md) | Optimization: a domain-independent core with domain adapters registered in coupling; own algorithms on the unit cube (no optimization library); every evaluation on its own reconstruction of a design snapshot, exact caching by dependency key; deterministic generator and in-order commits; checkpoints as run records replayed from their seed; fidelity levels never merged; robust samples as common random numbers with a stated source; one best candidate only for one objective; promotion as one undoable revision; topology optimization as a SIMP proof of concept | M8 |
| [ADR-000216](docs/decisions/ADR-000216-automation-api.md) | Automation API: Qt-free application services used by every interface (one mutation funnel, counted revisions, structured errors, sessions within a policy, an audit trail); proto3 contract generated at build time with one adapter and a compatibility check; a Unix-socket endpoint in the GUI and a headless host with calls on the owner's thread; gRPC through a separate grpcio bridge; batches and transactions on a copy as one undo step, project changes only; bounded result reads; Python and MCP on the same contract | M10 |
| [ADR-000218](docs/decisions/ADR-000218-linux-zip-distribution.md) | Linux ZIP: CMake install into a bundle layout and a project bundler (readelf, the loader, patchelf) with an explicit system-library policy; relative DT_RPATH and qt.conf; Python bundled and isolated; licenses from a curated component table; launcher checks before loading, diagnostics in the application; the final ZIP validated, also in clean containers | M11 |
| [ADR-000219](docs/decisions/ADR-000219-shape-function-energy-architecture.md) | Shape–Function–Energy direction: function computed from physical models, never from object categories; a Coupled Energy–Matter Engine in src/core/coupling that coordinates the independent solvers (exchanged quantities, transfer operators, scheduler) with an energy ledger; material state as properties of declared state variables; distinct geometry representations; a shared resonance vocabulary; effective properties as model results; multiscale through optional adapters; a twelve-stage roadmap | M12 |
| [ADR-000220](docs/decisions/ADR-000220-coupled-energy-matter-engine.md) | Coupled Energy–Matter Engine: a domain-independent engine module (src/core/multiphysics: quantities, field data, transfers, ledger, material and geometry state, physical systems, orchestrator) with participants and coupling models in src/core/coupling; a thermal domain; layered-slab reference systems whose every coupling is validated; physical systems as a project extension; coupled runs as jobs; planned couplings registered and refused |
| [ADR-000221](docs/decisions/ADR-000221-functional-structures.md) | Functional structures: a domain-independent functional module over scene objects (parameters through the optimization framework's scene bindings, content-keyed staleness, studies), analyses in the domains registered in coupling (cavity with losses and a Yee model, paraxial optical resonator, Webster horn, mechanical studies, photonic cell, periodic rod, coupled slab), candidates from the optimization framework, explanations computed from evaluations, a service, contract and panel |
| [ADR-000222](docs/decisions/ADR-000222-resonance-engineering.md) | Resonance engineering: one resonance description on the functional analyses (nature, decay, Q by mechanism); spectroscopy in dsp; lumped oscillator networks as a domain-independent module the domains assemble; Helmholtz resonators and coupled resonators; Duffing and Mathieu models; a resonant cavity as participants of the coupled engine; ResonanceService |
| [ADR-000223](docs/decisions/ADR-000223-metamaterials.md) | Metamaterials as functional structures: effective-medium analyses with domain methods (lumped-cell Bloch, mass-in-mass lattice, Helmholtz-loaded duct, oblique layers and retrieval, split-ring circuit, layered conductivity); effective materials with validity and derivation; provenance homogenized; CreateEffectiveMaterial | ACCEPTED |
| [ADR-000224](docs/decisions/ADR-000224-multiscale-materials.md) | Multiscale material modeling: representations and lineage in the project, voxel RVEs with potential-problem homogenization, Lennard-Jones reference calculations, external engines as adapters (none integrated), sequential and iterative coupling | ACCEPTED |
| [ADR-000225](docs/decisions/ADR-000225-dynamic-material-state.md) | Dynamic material state: states separate from definitions, constitutive models with state in their domains (plasticity, damage, viscoelasticity, phase change, hysteresis), a trial-commit update contract, time-stepped evolution through the coupled engine, records and commits with lineage | ACCEPTED |
| [ADR-000215](docs/decisions/ADR-000215-python-automation-plugins-help-demos.md) | Python API as a pybind11 module over the core plus a documented package (no physics in Python); the console, editor and Python plugins in a worker process, changes applied as one undoable composite; JSON workflows of registered actions on snapshots; explicit plugins (workflow packs, Python, native C ABI) never sandboxed and never loaded unasked; one Markdown help source generated at build time into an offline QTextBrowser help with ranked search and a central F1 topic registry; screenshots and demonstrations as application-level step sequences waiting on real events; nothing starts a physical output | M9 |

## Deviations from requests

Recorded in the decision that caused them:

* qmake is supported in addition to CMake (ADR-000204), on the operator's instruction.
* GoogleTest is vendored rather than fetched or installed (ADR-000204).
* The deviations of the V0.1 foundation from its request are listed at the end of ADR-000206.
* The deviations of the acoustic engine from its request are listed at the end of ADR-000207.
* The deviations of passive wave manipulation from its request are listed in ADR-000208.
* The deviations of the full-wave solver milestone from its request are listed in ADR-000209.
* The deviations of the mechanical milestone from its request are listed in ADR-000210.
* The deviations of the electromagnetic milestone from its request are listed in ADR-000211 and `IMPLEMENTATION_STATUS.md`.
* The deviations of the compute-backend work from its request are listed in ADR-000212.
* The deviations of the experimental-hardware milestone from its request are listed in ADR-000213 and `IMPLEMENTATION_STATUS.md`.
* The deviations of the optimization milestone from its request are listed in ADR-000214 and `IMPLEMENTATION_STATUS.md`.
* The deviations of the automation milestone (Python, plugins, help, Demo Studio) are listed in ADR-000215 and `IMPLEMENTATION_STATUS.md`.
* The deviations of the automation API from its request (gRPC through a bridge rather than C++ stubs; Buf replaced by a project compatibility tool; some solvers not yet startable through the API) are listed in ADR-000216, `docs/reference/AUTOMATION_AUDIT.md` and `IMPLEMENTATION_STATUS.md`.
* The deviations of the Linux ZIP from its request (no build on an older baseline; the clean-machine tests run in containers with a virtual display; the application's own license not chosen) are listed in ADR-000218 and `docs/release/RELEASE_REPORT.md`.
* The deviations of the coupled engine from its request (layered-slab systems only; no GUI panel; acoustic, force and fluid couplings planned; no multirate time coupling) are listed in ADR-000220 and `IMPLEMENTATION_STATUS.md`.
* The deviations of the functional structures from their request (no CAD import, no OpenCASCADE; rectangular cavities only; no force metrics; structures created through the API rather than a GUI editor) are listed in ADR-000221 and `IMPLEMENTATION_STATUS.md`.
* The deviations of resonance engineering from its request (coupled resonators as lumped networks rather than one finite-element model; no fluid resonances beyond lumped acoustics; nonlinear models lumped; the heated cavity's thermal model lumped) are listed in ADR-000222 and `IMPLEMENTATION_STATUS.md`.
* The deviations of the metamaterial work from its request (1D lattices only - no 2D/3D Bloch of continua; the split ring as a circuit model, not full-wave; isotropic library materials, so a saved effective material carries one principal component; negative effective values reported, not stored) are listed in ADR-000223 and `IMPLEMENTATION_STATUS.md`.
* The deviations of multiscale material modeling from its request (no external atomistic, molecular or electronic-structure engine is installed, so none is integrated and no electronic result exists; the atomistic pathway uses built-in Lennard-Jones reference calculations; RVE homogenization covers steady potential problems, not elasticity; FE2 and concurrent coupling are documented requirements; CIF and PDB import are not supported) are listed in ADR-000224 and `IMPLEMENTATION_STATUS.md`.
* The deviations of dynamic material state from its request (small strain only; no fracture propagation, fatigue, finite-strain plasticity or hyperelasticity; no nonlinear dielectrics, optics or acoustics; the coupled solvers carry temperature-dependent laws only, plastic and damage states run in their own studies; one-dimensional phase change) are listed in ADR-000225 and `IMPLEMENTATION_STATUS.md`.
* ADR-000219 sets a direction and implements nothing; the request's documentation paths were kept except the research roadmap, which lives with the milestone roadmap in `docs/architecture/` (instead of `docs/roadmap/`).
