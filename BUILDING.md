# Building and Testing Resonant

Resonant builds with **CMake** and with **qmake**. Both build the same
targets from the same sources (each target globs its directory), so use
whichever fits your workflow. After adding or removing a source file,
re-run the configure step: `cmake` does it by itself; for qmake run
`qmake6 -r ../../project.pro` in the build tree (the `-r` matters: without
it only the top-level Makefile is regenerated), or
`python3 scripts/devsys.py build fresh`.

The source is published at https://github.com/Pacmanfan/Resonant
(`git clone https://github.com/Pacmanfan/Resonant.git`).

## Requirements

| Dependency | Version used | License | Why |

| C++20 compiler | GCC 13.3 | — | language standard of the project |
| CMake | 3.21 or later (3.28 used) | BSD-3-Clause | build system |
| qmake | Qt 6 (`qmake6`) | — | alternative build system |
| Qt 6: Core, Gui, Widgets, OpenGL, OpenGLWidgets, Test | 6.4.2 | LGPL-3.0 (dynamically linked) | desktop application and OpenGL integration; Test only for the application tests |
| Eigen | 3.4.0 | MPL-2.0 | vectors, matrices, numerical linear algebra |
| OpenGL | 4.5 Core at run time | — | 3D viewport |
| nlohmann-json | 3.11.3, vendored in `third_party/nlohmann` | MIT | project files |
| GoogleTest | 1.17.0, vendored in `third_party/googletest` | BSD-3-Clause | tests only |
| pkg-config | any | GPL-2.0 (build tool only) | lets qmake find Eigen |
| xvfb (optional) | any | MIT/X11 | runs the application tests without a display |
| VOLK (optional) | 3.1.2 | LGPL-3.0 (dynamically linked) | SIMD kernels for single-precision data (display conversions, measured samples) |
| CUDA toolkit (optional) | 13.5 | NVIDIA CUDA EULA (runtime linked statically) | the optional GPU backend of the full-wave solvers |
| HDF5 (optional) | 1.10.10 | BSD-style (dynamically linked) | measurement data next to the project (otherwise a binary format) |
| ALSA (optional) | 1.2.11 | LGPL-2.1 (dynamically linked) | the audio-interface driver |
| SoapySDR (optional) | 0.8.1 | BSL-1.0 (dynamically linked) | SDR discovery |
| Python 3 (interpreter) | 3.12 | PSF | builds the in-app help (`tools/help/build_help.py`, standard library only); runs the console, scripts and Python plugins |
| Python development headers, pybind11 (optional) | 3.12, 2.11 | PSF, BSD-3-Clause | the Python API module `_resonant`; NumPy (BSD-3-Clause) at run time |
| protoc, libprotobuf (optional) | 3.21 | BSD-3-Clause | the automation API: the `resonant.v1` contract, its adapter, the headless host `resonant-automation` |
| grpcio, protobuf for Python (optional, run time) | 1.78, 6.33 | Apache-2.0, BSD-3-Clause | the gRPC bridge and the `resonant_api` client; `mcp` (MIT) for the MCP server |

On Ubuntu 24.04:

```bash
sudo apt install build-essential cmake ninja-build pkg-config \
    qt6-base-dev libqt6opengl6-dev libeigen3-dev libgl1-mesa-dev xvfb
```

Optional: `sudo apt install libvolk-dev` for VOLK, and NVIDIA's CUDA
toolkit for the GPU backend. Both builds find them by themselves and build
without them (`docs/compute/COMPUTE_BACKENDS.md`); the configure step
reports `Resonant acceleration: VOLK ON|OFF, CUDA ON|OFF`.

Optional measurement libraries: `sudo apt install libhdf5-dev libasound2-dev`
(and SoapySDR from its project). The CMake configure step reports
`Resonant measurement libraries: HDF5 ON|OFF, ALSA ON|OFF, SoapySDR ON|OFF`;
switches `-DRESONANT_WITH_HDF5|ALSA|SOAPYSDR=OFF`, qmake `CONFIG+=no_hdf5`,
`no_alsa`, `no_soapysdr`. The drivers are built into the separate
`resonant_hardware` library (`docs/experiments/HARDWARE_INTEGRATIONS.md`).

Optional Python API: `sudo apt install python3-dev pybind11-dev python3-numpy`.
Both builds find them (`python.pri`; CMake `RESONANT_WITH_PYTHON`, reported as
`Resonant Python API module: ON|OFF`; qmake `CONFIG+=no_python`) and build
without them; the module is `<build>/src/python/_resonant*.so`
(`docs/python/PYTHON_API.md`).

Optional automation API: `sudo apt install protobuf-compiler libprotobuf-dev`
(and `python3 -m pip install grpcio protobuf` for the gRPC bridge). Both builds
find them (`protobuf.pri`; CMake `RESONANT_WITH_AUTOMATION_API`, reported as
`Resonant automation API: ON|OFF`; qmake `CONFIG+=no_automation_api`) and build
without them. The C++ code and the descriptor set
(`<build>/src/automation_api/resonant_api.desc`) are generated from `proto/`;
nothing generated is committed. The headless host is
`<build>/src/automation_host/resonant-automation`
(`docs/reference/GRPC_CLIENT_GUIDE.md`). C++ gRPC is not needed.

The in-app help is generated by every build into `<build>/help`
(`docs/help/DOCUMENTATION_BUILD.md`); the build fails when a page has a broken
link, image or reference.

## Installing

```bash
make -C build/debug install INSTALL_ROOT=/tmp/stage     # qmake (PREFIX=/usr/local by default)
cmake --install build/release --prefix /opt/resonant    # CMake
<prefix>/bin/resonant --check-help                      # the installed help works
```

The application (and `resonant-automation`) go to `<prefix>/bin`; the help,
demonstrations, examples, example plugins, Python packages (`resonant`,
`resonant_api`) and the API's descriptor set to `<prefix>/share/resonant`.

Nothing in the build refers to a path on a particular machine.

## CMake

```bash
cmake -S . -B build/cmake-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build/cmake-debug

cmake -S . -B build/cmake-release -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/cmake-release
```

Options: `-DRESONANT_BUILD_APP=OFF` builds only the core library and its
tests (no Qt needed); `-DRESONANT_BUILD_TESTS=OFF` skips the tests;
`-DRESONANT_WITH_VOLK=OFF` and `-DRESONANT_WITH_CUDA=OFF` leave the
acceleration out; `RESONANT_CUDA_ARCHITECTURES` sets the GPU architectures
(default `75-real;86-real;89-real;120`).

The application is `build/cmake-debug/src/app/resonant`.

## qmake

```bash
mkdir -p build/debug && cd build/debug
qmake6 ../../project.pro                 # add CONFIG+=release for a Release build
make -j"$(nproc)"
```

qmake options: `CONFIG+=no_volk`, `CONFIG+=no_cuda`, `CUDA_DIR=...` (default:
the `nvcc` on the `PATH`, else `/usr/local/cuda`), `RESONANT_CUDA_ARCHS="75 86 89 120"`.

The application is `build/debug/src/main/resonant`. The repository's
development-control system uses this build
(`python3 scripts/devsys.py build build`, `... build fresh`).

## Tests

```bash
# CMake tree
ctest --test-dir build/cmake-debug --output-on-failure

# or the binaries directly (either tree)
build/debug/tests/core/resonant_core_tests
xvfb-run -a -s "-screen 0 1600x1000x24" build/debug/tests/app/resonant_app_tests
```

* `resonant_core_tests` — the core library. Needs no display and no OpenGL.
  It also runs the Python package's tests (`python/tests`) against the
  module of the same tree, and the strict help build; both are skipped or
  fail with the reason when the module or `python3` is missing.
* `resonant_app_tests` — camera mathematics, rendering into an offscreen
  framebuffer, and the real main window. Needs a display with OpenGL 4.5
  Core; `xvfb-run` with Mesa's software renderer is enough. On a desktop
  session it can run without `xvfb-run`, but it opens windows.

Both accept the usual GoogleTest options, for example
`--gtest_filter=Scene.*`.

Through the development-control system (builds with qmake, selects the
suites a change affects, records the run):

```bash
python3 scripts/run_tests.py --tier t2 --build      # everything a work item must pass
python3 scripts/run_tests.py --list                 # suites, groups and tiers
bash tools/verify_cmake_build.sh                    # CMake build + CTest (suite "cmake"; tree build/cmake-verify, Debug at -O1)
python3 tools/check_layering.py                     # layering rules (suite "layering")
```

## Warnings

Resonant's own code is compiled with `-Wall -Wextra -Wpedantic -Wshadow
-Wnon-virtual-dtor` and builds without warnings. Third-party code is
compiled without them. No warning is suppressed in Resonant's code.

## Known build notes

* Qt 6.4's `moc` cannot parse the C++20 syntax of libstdc++ 13 headers.
  Both builds therefore do not give `moc` the compiler's own include
  directories or predefined macros (`CMAKE_AUTOMOC_COMPILER_PREDEFINES OFF`;
  `MOC_INCLUDEPATH` in `warnings.pri`). This affects only `moc`.
* `resonant --screenshot <file> [project]` saves an image of the main
  window and exits; it is used to check the application on a virtual
  display.
